# decision-inbox

多会话协作时的决策收件箱。几个 Claude Code 和 Codex 会话一起干活时，要你拍板的事、谁在等谁、谁停下了，都集中到一个「决策收件箱」会话里。名称不清楚就用 `/decision-inbox:glossary` 查术语表（Codex 会话运行 `~/.decision-inbox/bin/decision-inbox glossary`）。

- **待答表**：各会话抛来的【等待用户】待决事项，按挡住几条线排序，一项一张卡片，推荐选项带好复制块；你回「12 A」，决策收件箱原话转达给提出方（多线事项分别转给各条线）。
- **等待记录**：谁在等谁的什么、等了多久，编号是 `W3` 这样的 W 编号（`#数字` 只给待决事项），只按四种理由关掉。
- **巡视**：一个专门的巡视会话用 `/loop 5m` 每 5 分钟跑一轮（侧边栏只有这一个会话；实际间隔受宿主影响，见排查）。停下或空闲积压 3 分钟的 Claude 会话先叫醒；决策收件箱发出的消息被 agent-relay 判为 offline 满 3 分钟，也改用桌面版会话消息叫醒；叫不醒、Codex 任务没打开或全线停住时提醒你，附上去哪里打开。线停住 12 小时、返工 3 轮或 24 小时内同一件事报批 3 次，巡视会请那条线自己抛一项【等待用户】，30 分钟没抛就在主视图列出选项。模块协调那条线还按模块看（需要 module-crew 0.4.0）：模块从最后一次提交（没提交过按开工时间）算起的出手时长超过 12 小时（等你答复的时间不算），或同一节点 24 小时内报批 3 次，巡视请模块协调就这个模块抛【等待用户】；已合入、等合并、挂起的模块不问，正在等你或正在审查的模块照样看，读不到提交时不按时间判断；已经提示「可能在打转」的模块（见「模块打转」）不再叫醒。巡视会话停了时，决策收件箱会顺带巡视：它被叫醒或你跟它说话时，巡视超过 10 分钟没跑就补一轮（通知直接显示在决策收件箱里）。每轮读到的原始状态留在 `~/.decision-inbox/<协作组>/io/snapshots/`，最多 24 份，方便查没叫醒的原因。
- **停止钩子**：有会话在等你时，工作会话收工前会被拦一次，提醒先交付或报阻塞。
- **查询**：各线状态、流畅度体检、单项时间线、能力图进度。

依赖：

- [agent-relay](https://github.com/haigeerlab/agent-relay)：会话之间的邮箱，必需；
- [spec-guard](https://github.com/haigeerlab/spec-guard-plugin)：可选，有了才能看能力图进度和进度预警；
- macOS、`python3`（3.10 及以上，只用标准库）、Claude 桌面版（决策收件箱和巡视任务都在桌面版里跑）。

## 安装

发布前从本地目录安装（把 `<仓库目录>` 换成这个仓库在你机器上的路径）：

| Claude Code | Codex |
|---|---|
| `/plugin marketplace add <仓库目录>` | `codex plugin marketplace add <仓库目录>` |
| `/plugin install decision-inbox@decision-inbox-marketplace` | `codex plugin add decision-inbox@decision-inbox-marketplace` |

装好后开一个新会话，插件的命令、技能和钩子才会生效。

### 固定副本安装（演练与接入用）

从开发目录安装时，开发目录一变，装好的插件就跟着变。演练和正式接入要用一个不会再变的副本，两个宿主都从它安装：

1. 在仓库里给要冻结的提交打标签，再检出一个独立副本：`git tag v<版本>`，`git worktree add --detach <副本目录>/v<版本> v<版本>`。
2. 两个宿主都把 `decision-inbox-marketplace` 指向这个副本目录，再重装插件：
   - Claude Code：`claude plugin marketplace remove decision-inbox-marketplace`，`claude plugin marketplace add <副本目录>/v<版本>`，`claude plugin install decision-inbox@decision-inbox-marketplace`；
   - Codex：`codex plugin marketplace remove decision-inbox-marketplace`，`codex plugin marketplace add <副本目录>/v<版本>`，`codex plugin remove decision-inbox@decision-inbox-marketplace`，`codex plugin add decision-inbox@decision-inbox-marketplace`。
3. 重开会话，在不属于任何插件仓库的目录里运行 `doctor`：「Claude、Codex 两边的版本」应为同一个版本，「转发脚本」指向副本目录。

Codex 会把装好的副本缓存在自己的目录里，只改市场不重装，Codex 会话仍跑旧版；启动时它还会把转发脚本切到自己那一份。所以两边一定都要重装，并用 doctor 核对。

## 接入

已经在项目规则文件里手贴过决策收件箱规则的，接入前先删掉手贴的旧决策收件箱规则，只保留协作规则段这一份来源。

按这个顺序接入，每一步都会先预览要写哪个文件、写什么，你确认后才写：

1. **决策收件箱**：为它单独建一个目录，在这个目录里开一个 Claude 桌面版会话，运行
   `/decision-inbox:hub-setup <协作组名> <它在 agent-relay 的邮箱名>`。
   它会建协作组、把决策收件箱的约定写进本目录的 `CLAUDE.md`、开一个巡视会话（`/loop 5m`；开在 `~/.decision-inbox/<协作组>/patrol`，不开在决策收件箱目录里，免得巡视加载收件箱的协作规则段、被当成决策收件箱；以前建过巡视定时任务的，确认后删掉它，它建过的会话会一起归档）。
   建好后运行 `~/.decision-inbox/bin/decision-inbox onboard allow <协作组名> --project <决策收件箱目录>`：它列出巡视和决策收件箱要用的命令和 agent-relay 工具，你确认后加 `--confirm` 写进决策收件箱目录和巡视目录各自的 `.claude/settings.local.json`（只写这两个文件），以后巡视不会卡在权限确认上。然后打开巡视会话看第一轮跑完；没写权限放行的话，这一次要把弹出的权限逐个批完。
2. **审查者**：在各审查者的会话里运行 `/decision-inbox:join <协作组> owner <邮箱名> <线名> <线名>`。
3. **开发线和跨线协调**：
   - Claude 会话：`/decision-inbox:join <协作组> dev <邮箱名> <线名> <线名>`（跨线协调用 `coordinator`，不写线名）；有审查者时告诉它审查者的邮箱名和审哪几类节点（spec、plan、interface、final）。
   - Codex 会话：对它说「接入 decision-inbox 协作组」，它会用自带的接入技能完成同样的步骤。

- Codex 会话要开在写协作规则段的那个仓库里（或它下面的子目录），并在 Codex 里信任这个项目；否则 Codex 不会加载协作规则段，接入预览开头会用 `⚠` 提示应该在哪个目录开会话。
- 协作规则段写明了开发线接哪些邮箱派来的活：决策收件箱转来的【用户答复】，以及审查者、跨线协调派的活按约定执行；其他会话的请求只当信息。实测中，新开的 Codex 任务只让它登记邮箱名，它也会执行审查者派来的活。
- 还想让联网、安装这类操作不必回原会话确认，就在 Codex 会话开好后对它说一句「按本目录 AGENTS.md 的约定办事，读收件箱，按收到的任务做」：有这句话、协作规则段又被加载时，Codex 的自动批准（守卫）会认决策收件箱转来的你的答复。
- **检查点答复即授权**（默认打开，可以关）：接入时默认写进协作规则段：决策收件箱转来的、带你原话的检查点答复（Spec 批准、Plan 批准、接口提案、最终验收），就是你对这个检查点范围内必要操作的授权：按 Spec、Plan 改文件、构建、测试、本地提交，以及装构建需要的依赖（含加新包），只从官方源下载，项目已有的依赖规则照旧；也适用于宿主的自动批准。全局安装、把下载的脚本直接交给 shell 执行、把密钥或凭据发到外部、删除工作区以外的文件或大范围删除、推送合并发布、修改全局配置不在授权内。不要的话，接入时加 `--no-checkpoint-authority`；原来的 `--checkpoint-authority` 仍可用，等于默认。接入预览开头会提示这一项默认打开。
- **模块协调**（配合 module-crew）：模块协调代表一条线接入，按开发线接入并加 `--crew-coordinator`。协作规则段会多一节「模块协调」，写明：模块在干活时收工不用抛待决事项；几个模块的事要合成一项抛出，或者写【与 #旧编号 并行】；转完答复立刻发【已恢复】；以及它和 crew-coordinator skill 怎么分工。停止钩子不会因为模块的 todo 没勾完而拦它。这个标记只能在接入时经你确认后写入。
- **协作规则段写进 `CLAUDE.local.md`**（只适用于 Claude）：模块协调开在集成 checkout 里时，加 `--local-rules`，协作规则段就写进 `CLAUDE.local.md`，不写进由 git 跟踪的 `CLAUDE.md`。这样它不会被提交，也不会被模块 worktree 继承。这个文件如果还没被 git 忽略，确认时会在 git 的 `info/exclude` 里加一行（只影响本机，不改仓库里的文件），卸载时再删掉。注意：项目里只有 `AGENTS.md`、没有 `CLAUDE.md` 时，加了 `CLAUDE.local.md` 之后，Claude 默认就不再读 AGENTS.md（宿主差异 H26），接入预览会提示。

每个会话接入后还要做两件事（命令会提示）：

- 在 agent-relay 登记邮箱名并绑定唤醒（`bridge_register`，`wake: "auto"`）；
- 在 Claude Code 和 Codex 里各信任一次插件自带的停止钩子。

约定会写进各项目的 `CLAUDE.md`（Claude）或 `AGENTS.md`（Codex），用 `<!-- BEGIN decision-inbox … -->` 和 `<!-- END … -->` 包住，块外的内容一字不动；重复接入会整块替换。

### 替换已有的决策收件箱

原来已经有一个决策收件箱（比如手贴规则版）在用、并且编过号时，新决策收件箱接入时加 `--start-number <起始编号>`（例如 1001），待决事项和等待记录就从这个号开始编，不会和旧编号混在一起。起始编号只能在新组还没编过号时设；重跑接入可以带同一个值。

切换前，先让各会话把未读消息处理完：新决策收件箱会把当下的未读积压照常算进主视图和巡视。agent-relay 里的历史「欠回复」（`owesReplies`）本插件不读，切换后不会显示成积压。

### 迁移期：还没接入的会话

原来有一套手写规则在跑、各线分批切换时，还没切换的开发线先用 `~/.decision-inbox/bin/decision-inbox onboard enroll <协作组> --relay-name <邮箱名> --short-name <线名> --host <宿主> --line <线名>` 登记进名册（预览后加 `--confirm`）。这一步只写名册，不写协作规则段，条目标为「旧格式」。在它正式接入之前：

- 决策收件箱发给它的答复用旧规则认得的编号写法：普通答复写 `事项：#<它那条消息的邮箱号>（hub 编号 N）`，多线答复写 `事项：#<发起方那条消息的邮箱号>（多线事项，发起方 <邮箱名>；hub 编号 N）`；
- 不给它发【答复告知】（旧规则里没有这种消息），审查者的决定仍按旧路线转交给它；
- 它用自己的邮箱号写的【取代】【撤回】，决策收件箱也认（只限它自己还没结束的待决事项）。

它以后用 `/decision-inbox:join` 正式接入时，「旧格式」标记自动去掉，从此用正式写法。要把它移出收件范围，就用 `onboard leave`：名册条目保留，决策收件箱不再给它发任何消息。leave 的预览会列出它名下还没结束的待决事项和开着的等待记录。doctor 对这类条目报「只登记，不写协作规则段」，属正常。

## 日常使用

平时只看决策收件箱，直接对它说话：

| 你说 | 它做什么 |
|---|---|
| `12 A`、`12 B 但先别上线`，或复制卡片里的代码块（复制块） | 把你的原话转达给提出方；末尾多带的引号、句号（如 `12 A」`）照样认作 A |
| `12 原话：先这样，下周再说` | 不选选项，把你的话原样转过去；写了编号却认不出选项字母时，会先问你选哪个，不会悄悄转出去 |
| `21 A；D1 B；D2 A` | 待决事项带「待你决定的问题」（D1、D2…）时，主选项和每个 D 都要答；少答、答错字母会被追问，不会转发半截答复，也不会按审查倾向替你默认 |
| 复制主视图末尾「一次答完（全按推荐）」的代码块 | 几项同时等你时，一次全按推荐答完 |
| `看 12` | 只看这一项的卡片 |
| `看 12 全文` | 看卡片背后的全部原文：交审原文、产物全文、审查原文、完整的内容要点（已结项的也能看）；一个代码块都不用，单个文件超过 300 行只显示前 300 行 |
| `12 详情` | 显示待决事项全文、各线范围和消息编号 |
| `看等待`、`看已关闭`、`看已关闭 2026-10-15`、`看失效` | 展开对应明细 |
| `看 W5` | 看一条等待记录从开到关的经过 |
| `关掉 W5 已经不需要` | 按「用户关闭」关掉等待记录（写 `关掉 #5` 也认）；「看等待」里标着「可能已失效」的等待记录通常就是这样关掉：一种是发送方之后又发过消息、却没结束它（新开的【等待其他会话】不算，模块协调的等待记录不做这个判断）；另一种是「等什么」里点名的、发送方自己的待决事项已经结项（结束、取代、撤回；模块协调的也算）。「在等谁」写「决策收件箱（邮箱名）」也算在等你，你的答复发出去后这条自动关掉 |
| `12 挂起`、`12 换方案：先只做第一页`、`12 继续等` | 只在带「可能在打转」提示的待决事项上用（见下面「模块打转」）：原话转给提出方；「继续等」后这个模块 12 小时内不再提示 |
| `看模块 alpha` | 列出这个模块问过你的全部待决事项（每项一行：第几次、问什么、结果）和它的问询次数、基准、开工时长 |
| `重发`、`重发 12` | 重新列出没发出去的消息（全部，或只与 #12 有关的） |
| `以后 X 都这样` | 先问你发给哪几个会话，确认后原话转过去 |

查询命令（只读，不给任何会话发消息）：

- `/decision-inbox:lines`：各线状态；
- `/decision-inbox:flow`：流畅度体检，卡在哪、谁等谁；
- `/decision-inbox:item <编号>`：单项时间线；
- `/decision-inbox:waits`：在工作会话里查自己：我在等什么（我开的等待记录、我抛出还没结的待决事项及其答复送到没有）、谁在等我，各带等了多久和对方离线、可能已失效的标记；不催办，该等还是该催由会话自己定；
- `/decision-inbox:map [线|all] [全部]`：能力图进度；审查列写「✔／待批准／改过待重审／无标记／标记无效」（和 spec-guard 的 `/map` 写法一致），有外部审查参考意见时加「（有参考意见）」。

体检与统计（命令行，只读）：

- `~/.decision-inbox/bin/decision-inbox doctor [--group <协作组>]`：逐项核对协作规则段是不是当前版本、转发脚本指向、巡视、Codex 能否加载协作规则段、Codex 钩子信任、依赖插件版本与接口（module-crew 另写契约版本；名册里有模块协调时，还实际读一次它的只读出口，报读到几个模块或读不到的原因）；每项写来源和怎么做，有异常时退出码 3。`--json` 给程序读（`schemaVersion` 1，字段 `name`、`state`、`source`、`evidence`、`fix`），`--report` 出一份可以直接转给负责方的异常报告（不含消息正文）。
  - 「宿主权限：<线名>」（每条开发线一项，只读）：读这条线宿主的实际权限（Codex：沙箱模式、能不能联网、项目受不受信任、仓库里的 `.codex/config.toml`；Claude：有没有放行加新包的规则、旧版写的先问规则删了没有），和这条线仓库要装什么对照：仓库根目录有依赖清单（`package.json`、`pyproject.toml`、`requirements*.txt` 等）就算要装依赖，不再读 Plan。要装依赖、宿主却不让时报 ✘；`package.json` 有 `dev` 脚本时，另查 Claude 有没有放行开发服务命令、Codex 不能联网时提醒界面自验用的浏览器可能下载不了。给两个选项：A 你自己改（Codex 在受信任项目的 `.codex/config.toml` 写 `[sandbox_workspace_write]` 和 `network_access = true`，不改 `~/.codex/config.toml`；依据 openai/codex 源码，Codex 桌面应用没实测，改完在开发会话里试一次。Claude 重跑接入）；B 不改，开发线碰到时按「去会话操作」上报，到时去那个会话点。仓库根目录没有依赖清单时只列宿主事实，不算异常。决策收件箱不改任何宿主配置。开发线接入时，预览里也会对照一次。
- `… query stats <协作组> [--since 2026-10-17] [--json]`：待决事项数、绕过决策收件箱结束的待决事项、抛出→答复与答复→恢复的耗时（中位、最长）、被取代／退回／追问被退回／拒收转述次数、开着的等待记录、巡视实际跑了几轮和相邻两轮的最长间隔。
- `… query events <协作组> --json [--since <日期>]`：事件日志，每条固定为 `at`、`kind`、`actor`、`item`、`data`。

### 要你去会话里操作

这类卡片排在主视图最上面，不用回复，也没有复制块：

- 开发线自己报的「去会话操作」：`**#N · 去 <会话> 点一下弹窗**`，写被拦的操作、点哪个按钮、为什么这里批不了、去哪（Claude 带链接，Codex 写在 Codex 应用里打开哪个任务）；你在别的待决事项里已经同意过的，会写「你在 #N 已同意，只差宿主这一下」。点完后对方发【已恢复】，这一项自动消失；满 30 分钟还没结项，会标「再提醒一次」。
- 没人报、收件箱自己发现的：巡视和收件箱读 agent-relay 的 `bridge_sessions`，看到这个协作组的某个 Claude 会话（名册里的会话，或模块协调开出来的模块会话）停在权限弹窗上满 5 分钟（`group.json` 的 `stall` 下用 `promptMinutes` 改），而这条线没有开着的「去会话操作」，就出一张「**去 <会话名> 点一下弹窗**（收件箱发现的，提出方没报）」，附链接和点「允许」／点「拒绝」各适用什么；巡视的桌面通知每次弹窗只发一次。「停在弹窗」按 `status: waiting`、`waitingFor` 含 permission 判断（2026-10-19 用一个停在真弹窗上的会话实测过，`bridge_sessions` 报的正是 `waiting`／`permission prompt`）。Codex 任务不在 `bridge_sessions` 里，照旧靠「去会话操作」上报。
- agent-relay 看到 Claude 线停在确认上、它又没上报时，照旧有「去原会话确认」卡片兜底。

### 模块打转

打转的数字不写在卡片抬头上（卡片按模板只给结论），写在主视图的「在做的模块」一段和「看模块 <id>」里：第 n 次问你（基准 M，超出第 k 次）、你答了 j 次进度没动、开工多久、进度 a/b。

- 模块：【等待用户】写了「模块：<id>」就用它（契约 v2.4），写「模块：无」是线级的待决事项，不计入任何模块；交审写的模块；单模块开发线取收到时它的当前模块；模块协调转来的没写模块时，依次按「要你决定」第一行对上 module-crew 的【等待用户】、交审编号（如 C184）、模块会话的邮箱名、「要你决定」里唯一出现的模块 id 来认，几个模块的编号同在一项里的算合问，不归任何一个；都认不出写「模块未知」，后面的计数不写，之后每轮按内容再认一次。
- 基准 = Spec + Plan + gate 检查点个数（spec-guard 0.77.0 起的 `gates.total`，旧版本写「基准未知」）。去会话操作和被取代的不计入次数。
- 「进度没动」：单模块开发线看你每次答复到下次答复之间这条线仓库有没有新提交；模块协调线用 module-crew 0.5.0 的 `answers`（有没有提交或勾 todo）。读不到时写「进度读不到」。
- 开工时长扣掉等你答复（含去会话操作）和等别的线的时间；等你答复算到答复发送成功为止，没发出去一直算等。巡视判断模块停滞时，从最后一次提交、开工、你最近一次答复送达三者中最晚的那个算起，合问对涉及的每个模块都扣，模块协调的等待记录点名了模块的只扣那个模块、没点名的扣它手上所有在做的模块。
- 这个模块以前问过的待决事项，用「看模块 <id>」看，一行一项。
- 主视图在线状态下面加「在做的模块」一段，每个在做的模块一行：问了几次、基准、开工多久、最后一次进展多久前。

满足任一条就提示「可能在打转」（阈值可在 `group.json` 的 `stall` 下改：`loopAnswers`、`loopHours`、`loopQuietHours`）：你答了 2 次、之后模块又来问，两次中间进度都没动；或答复后没进展的出手时间累计满 12 小时。提示出现在这个模块开着的待决事项顶上，附三个回复写法：`N 挂起`（挂起它、先开可开工的模块，由那条线自己挂起）、`N 换方案：<怎么换>`、`N 继续等`（12 小时内不再提示）；主视图最上面同时挂一行提醒。只提示，不拦它，也不替它挂起。这三个词不是契约里的选项字母，按你的原话转给提出方，协作规则段写明了它们的意思。

### 并行开发线在主视图里怎么显示

接了 `--crew-coordinator` 的模块协调，代表一条由 module-crew 并行开发的线。主视图、`/decision-inbox:lines` 和巡视会在它的仓库里运行 module-crew 在 `interface.json` 里发布的只读出口（`sessions --json`，只认接口 1.x、schemaVersion 1，3 秒超时），列出各模块，不读 module-crew 的状态库：

- module-crew 0.3.0 起出口带审查状态时，模块写「返工中（审查第 N 轮）」或「审查中」，取代阶段词；旧版本没有这个字段，照旧显示阶段；
- 只要有一个没挂起的模块会话在忙（按 agent-relay 的忙闲），这条线就是「干活中」，不算阻塞，也不参与「全线互等」；模块协调开着的等待记录全部写在括号里，例如 `干活中（模块 a 在忙·构建、b 停着·等合并、c 挂起：等接口；还在等 API #1203、#1204）`；
- 没有模块在忙时，照常按模块协调的等待记录判阻塞、参与全线互等，括号里照样列出模块；
- 出口读不到时写「模块状态未知：原因」，这时不报全线互等；
- 这条线不判「停住」，模块进度归 module-crew。

回复里只有不带字母的数字（`21`、`#21`）是待决事项号。交审编号 `C15`、审查编号 `R-3`、问题编号 `D1` 都原样留在你的原话里转过去，不会被当成别的待决事项；`21 B，C15 退回` 这样写，认作答 #21 选 B。

决策收件箱收下一项【等待用户】后，会静默回发件会话一条【登记回执】：待决事项号、取代了哪几项、写法提示（缺「项目」、你该回只写字母等）。发件会话写【取代】【撤回】时用回执里的待决事项号。迁移期还没接入的会话不发回执。

### 卡片怎么读

每张要你决定的卡片按 `DECISION-CARD-TEMPLATES` 的 7 类写，只给结论，整张卡十几行：

1. **抬头**：`**#N · 要你定什么** · 等了多久 · 挡住几条线`；第二行写项目、线、模块、类别，提请批准的另写第几次交审、上次你答了什么。
2. **内容要点**：上游按契约 v2.3 写了「类型」和固定小项的（Spec 的目标、做／不做……最终验收的做了什么、验收结果、改了哪些文件……），按模板顺序每项一行，只取第一行，其余写「（共 N 行，见「看 N 全文」）」；旧写法的待决事项从「要点」里挑：「验收标准与证据」压成一行「验收标准 N 条，标了通过的 M 条」，其余最多 6 行。
3. **结论**：有审查原文时写谁审的、过没过、审查编号、须修改几条和第一句理由；没有就用「架构审查：」的标签；都没有写「未审查」。**注意**照上游写的显示（写「无」就显示「无」）。
4. **各选项选了会怎样**，非推荐项后面写答复写法；**推荐**后面接推荐理由；「批了会怎样」放在内容要点最后。
5. **复制块**：每张要你回答的卡片恰好一个代码块，放推荐答复（带 D 决定时合在同一行，如 `40 A；D1 A`）；不用回答的东西（原文、日志、示例、主视图其他区块）一个代码块都没有。两项以上待答时最后有「一次答完」，提请批准的待决事项也算在里面。

类别：能力图审阅、Spec、Plan、Spec 与 Plan（合审时一张卡）、中途检查点、最终验收、接口提案（按 Spec 卡写）、卡住时选做法、去会话操作（不用回复）。上游没写「类型」时按交审节点分，分不出的按「卡住时选做法」的外框显示。

原文默认不展开：回「看 N 全文」看交审原文、产物全文（重交时先给与上一版的差异）、审查原文和最终验收的「验收标准 ↔ 证据」对照（缺的标「⚠ 缺证据」）。原文读不到时（文件不在、提交不存在、指纹对不上、不在 git 仓库里），那一段写「原文取不到」和原因，不拿要点顶替。原文由插件命令在自己的进程里读，不经过会话的读文件工具，所以不会因此弹权限确认。一项里合了几个模块时按模块分节，回执会提醒发件会话「按决定 47 应各自一项」。

收件箱会话每轮结束时，停止钩子会对照它这一轮跑出的主视图检查最终回复：卡片抬头、复制块少一个或改一个字，或者没有待答的待决事项却出现了代码块，就拦下来让它逐字重贴（一轮只拦一次）。doctor 的「收件箱停止检查」一项报告它读不读得懂本机的会话记录。

你答复后，卡片显示「已收下你的答复」；要等 `inbox sent` 记下发送成功才算「已转达」。发失败时写明哪一项、发给谁、什么原因（例如提出方已撤回的请求被一并关掉时 agent-relay 整条拒收，收件箱会去掉那一项，说「重发 N」即可），那一项在主视图显示「已答复，待发送」。

决策收件箱不替你决定、不改写选项、不批宿主的权限确认；要你去某个会话里亲手点确认时，它会明说。

决策收件箱只认你在它的会话里亲手输入的话。别的会话发来的消息（包括替你传话的测试或模块协调）不会被当作答复，它会提示你亲手再说一遍。注意：程序看不到一句话是谁输入的，这一层靠决策收件箱遵守约定来判断来源。

开发线对答复有疑问时，决策收件箱会自动回一条固定说明（写明待决事项编号和它自己的原消息编号的对应关系），并在主视图的异常里记一行；它不会自己答疑。

审查者抛的待决事项被你答复后，决策收件箱会给在做这一项的那条开发线发一条【答复告知】（按审查编号找提交方；没有审查编号时，按模块找唯一有这个模块的开发线；都认不出就不发，由审查者自己转交）：只是让它们知道答复已经有了，不是批准，开发线要等审查者转交后才执行。

## 消息协议

各会话之间的消息格式（【等待用户】【用户答复】【等待其他会话】【已恢复】【撤回】【审查结论】【答复告知】、结束写法、问题代码等）以共用契约 `session-protocol` v2.6 为准，本插件的测试里逐份跑契约样例（`tests/fixtures/session-protocol/v2.6/`）。v2.6 起「待用户决定」的编号也可以写成 C 待定编号（如 C15-1，交审 C15 下的第 1 个待定问题），答法「C15-1 B」「C15-1：B」「C15-1 选 B」都认；Spec 卡的小项可写上游的「边界」「未决问题」，Plan 卡开头可加「架构决定」、末尾加「未决问题」，新旧名都认、各显示各的。v2.5 起【等待用户】【审查结论】可写选填的「任务：T<n>」（module-crew 的轻任务），卡片抬头显示任务；用户原话里的 T 编号不当待决事项编号。v2.4 起【等待用户】可写选填的「模块：<能力图模块 id>」（跨模块或线级写「模块：无」），紧跟「要点」；决策收件箱以它为准，没写时自己反查（见「模块打转」）。v2.3 起【等待用户】的「类型」另有能力图审阅、Spec、Plan、Spec 与 Plan、中途检查点、最终验收、接口提案、卡住选做法八种，「要点」里按类别写固定小项，另有「注意」「推荐理由」「批了会怎样」三个选填字段；v2.2 的解析器会把这些取值整条退回，所以发这类卡片的一方要等决策收件箱升级后再发。v2.2 起【等待用户】可写「类型：去会话操作」：开发线停在宿主确认（弹窗、提权）上、决策收件箱批不了时，用它告诉你去哪个会话点什么；这类待决事项不用回复，放在主视图最上面「要你去会话里操作」一栏，满 30 分钟还没结项会再提醒一次，发起方点完后发【已恢复】自动结项。v2.1 起【等待用户】可带「产物」「交审原文」「审查原文」，见「卡片怎么读」。v2.0 起有【登记回执】、【等待用户】与【审查结论】的「待用户决定」、「有须修改项N条」与「须修改」，以及编号前缀（C／R／D）；【审查结论】改由审查者交给模块协调，可以静默抄送决策收件箱，决策收件箱只数审查轮次，不据此产生待决事项。0.0.21 起钉 v2.0.1，module-crew 要同为 2.x，doctor 才报兼容（0.2.x 讲 1.9，会报不兼容，要和 module-crew 0.3.0 一起换）。v1.1 起契约里另有【交审】【公共变更请求】【协调通知】三种消息，供多模块并行开发的插件使用；本插件不解析【交审】【公共变更请求】【协调通知】，一致性测试跳过这三类。v1.6 起另有【负责人转交】（审查者发给本线的开发线或跨线协调），以及跨线协调转给开发线的、带「转自」的【用户答复】。决策收件箱收不到这两种，一致性测试也跳过它们。协议要改时先改契约，再改本插件；契约的改动由用户批准。

## 使用注意事项

- 别的会话或代理替你开出来的 Claude 会话里，确认框也会弹，但弹在那个会话里；你不在跟前时，看到确认先看清是什么，不要顺手点允许。（2026-10-19 查证：stall-and-patrol 的 E3 里代开会话的推送弹了确认、被点了允许，当时误记成「没弹」；判断弹没弹，看会话记录里的 `permissionDecision.source`。）

| 现象 | 原因（来源） | 你怎么做 | 有问题找谁 |
|---|---|---|---|
| 决策收件箱或审查者一阵子没反应 | Claude 桌面版会停掉空闲会话，agent-relay 叫不醒（宿主） | 巡视会用会话消息工具叫醒；巡视也停了就手动点开 | 巡视叫不醒时找本插件 |
| 主视图写「巡视 N 分钟没跑」 | 两种可能：定时任务停在权限确认上；或宿主没按时触发（周期任务实际间隔不规律，宿主差异 H24） | 去定时任务列表看最近一次运行：停在权限确认上就批完（或运行 `onboard allow` 放行）；没有在跑的就立即运行一次 | 宿主限制；放行后仍停在权限确认：本插件 |
| 重启 ChatGPT 后 Codex 线都不动 | Codex 会话不会自动加载（宿主） | 逐个点开协作中的 Codex 会话 | 宿主限制 |
| Codex 开发线不按约定办事 | 会话开在接入的仓库之外，协作规则段没被加载（宿主） | `doctor` 看「Codex 加载协作规则段」，在接入的目录里新开任务 | doctor 报得不对时找本插件 |
| 读收件箱提示邮箱名不是本会话 | Codex 会话丢了联调用的邮箱名（agent-relay） | 按提示用原名重新登记 | agent-relay |
| 主视图异常区写「送达存疑」 | 对方接受了唤醒却一直没读，多半是任务的信箱连接断开（agent-relay 0.8.2 起标出） | 完全退出 ChatGPT 再打开那个任务 | agent-relay |
| 开发线要你回原会话确认 | Codex 自动批准不认转来的批准（宿主） | 决策收件箱会把它列成待决事项；去原会话亲手确认 | 宿主限制 |
| 决策收件箱某条命令被拦下 | Claude 自动模式拦了这类命令（宿主） | 按决策收件箱讲的原因处理，不要换写法绕过 | 宿主限制 |
| 报「全线停住」但有线在干活 | 旧等待记录没关；发送方后来又发过消息的、或者所等的待决事项已经结项的等待记录会标「可能已失效」，不计入（本插件设计；前一种不判模块协调，后一种模块协调也判） | 「看等待」，关掉不需要的等待记录 | 本插件 |
| Claude 会话不按项目的 `AGENTS.md` 办事 | 项目只有 `AGENTS.md`，又加了 `CLAUDE.local.md`，Claude 就不再读 AGENTS.md（宿主差异 H26） | 在项目里放一个 `CLAUDE.md`，写一行 `@AGENTS.md` 导入；或者在 Claude 设置里让它两种文件都读 | 宿主限制 |
| `doctor` 报某个依赖插件「读不到接口说明」 | 那个插件的版本早于提供 `interface.json`（依赖插件） | 升级那个插件 | 那个插件 |
| 主视图或通知写「名册过期：<线名> 的邮箱名已由新会话持有」 | 新会话用 `bridge_register` 接管了这个邮箱名，但没有重跑接入，名册里还是旧会话的编号（agent-relay 的实际绑定与名册不一致） | 在新会话里重跑 `/decision-inbox:join`（决策收件箱自己是 `/decision-inbox:hub-setup`），传入新会话的编号；重跑前巡视会改唤醒新会话，新会话没在运行时不唤醒 | 本插件 |
| 一句不是答复的话被记成了某项的答复，或者答复还没发出就想改 | 只剩一项待答时，不带编号的话以前会被当成那一项的答复（0.0.37 起只认选项字母或「原话：」） | 答复还没发出：说「撤下 N」撤回这次答复，#N 回到待答；或直接重新答「N X」替换。已经发出的撤不回，直接告诉提出方 | 本插件 |
| 不知道问题该报给谁 | — | 运行 `doctor --report`，按每项的「来源」转给负责方 | — |

## 卸载

1. 在各工作会话里运行 `/decision-inbox:leave`（Codex 会话说「退出 decision-inbox 协作组」），删掉规则文件里的协作规则段。
2. 在决策收件箱里运行 `/decision-inbox:teardown`，删掉它的协作规则段、卸掉巡视提醒（launchd 任务）、归档巡视会话（以前建过巡视定时任务的也删掉）。
3. 卸载插件：Claude Code 用 `claude plugin uninstall decision-inbox@decision-inbox-marketplace`；Codex 用 `codex plugin remove decision-inbox@decision-inbox-marketplace`。

`~/.decision-inbox` 下的状态目录（名册、待决事项、等待记录、事件日志）**保留**，不会被删除；确实不要了再自己处理。

| leave 预览写「还有没了结的事」 | 这个会话抛出的待决事项还没结束，或它还开着等待记录。leave 照常执行，但这些待决事项会留在主视图里：待决事项最好在 leave 前由它自己发【撤回】，等待记录你可以在决策收件箱说「关掉 #编号」 |
| 会话刚做完一轮，主视图就写「掉线」 | 0.0.20 起，桌面版收起空闲会话（agent-relay 报 `stopped`）时，只要登记了桌面会话编号或有唤醒绑定，就不算掉线，按其他情况判断；模块会话写「停着」。仍写「掉线」的，是叫不醒的：没登记 `--desktop-session`、没有唤醒绑定，或者 Codex 任务没打开 |
| 巡视运行一直「运行中」，后面的运行都没跑 | 多半卡在权限确认上：上一次没跑完，宿主会跳过之后到点的运行。打开那次运行的会话批完；升级到 0.0.20 后按「升级」一节重跑 `onboard allow`、换上新的巡视提示词，巡视就不再需要确认 |
| 不确定装对没有 | 运行 `~/.decision-inbox/bin/decision-inbox doctor`，按每项的「怎么做」处理 |
| 停止钩子不拦 | 在那个会话的工作目录运行 `~/.decision-inbox/bin/decision-inbox whoami`：退出码 4 是没接入，5 是同一个目录对上了多个协作组；钩子出任何问题都会放行，不会卡住会话 |
| 弹出系统通知「决策收件箱：巡视停了」 | 巡视提醒（`onboard watch` 装的 launchd 任务，每 5 分钟检查一次）发现巡视超过 15 分钟没跑：按通知里写的去巡视会话批完权限确认或重新发一次循环提示词；巡视恢复后不再弹，停着时每 30 分钟提醒一次。一直不弹：运行 doctor 看「巡视提醒」一项；系统设置里「通知」要允许「脚本编辑器」 |
| 只想卸掉巡视提醒，不卸决策收件箱 | teardown 会把协作规则段、巡视会话一起卸掉 | 运行 `~/.decision-inbox/bin/decision-inbox onboard watch <协作组> --remove` 看预览，确认后加 `--confirm`（只删 launchd 任务） | 本插件 |
| doctor 的「巡视提醒」报「上次运行退出 N」或「是旧版装的」 | launchd 任务装上了但跑不起来。日志里有 `Operation not permitted`（退出 126）：跑的程序在 `~/Documents`、`~/Desktop`、`~/Downloads` 下，launchd 没权限读；退出 1、日志是 Python 报错：launchd 用的 python 低于 3.10。都是 0.0.31 装法的问题，升级到 0.0.32 后重跑 `~/.decision-inbox/bin/decision-inbox onboard watch <协作组> --confirm`。日志在 `~/.decision-inbox/<协作组>/patrol-watch.log` |
| 主视图第一行写「巡视还没跑完过一轮」或「巡视 N 分钟没跑」 | 在定时任务列表里打开这个任务：最近一次运行停在权限确认上，就批完；没有在跑的运行，是宿主没按时触发，立即运行一次。`query stats` 能看到这段时间巡视实际跑了几轮、最长隔多久 |
| 决策收件箱跑 `inbox reply --relayed-from` 被自动模式拦下 | 转来的话同样不生效，只是少记一条事件；要留记录，请在决策收件箱会话里批准这一次 |
| 巡视不跑 | 在定时任务列表里看任务是否启用、最近的运行记录；建好后是否手动「立即运行」过一次（第一次手动运行之前，定时不会触发） |
| 决策收件箱换了会话、沿用原邮箱名接入时 `bridge_register` 被拒 | 名字还绑在旧会话上（agent-relay）：旧会话不用了就同意接管，决策收件箱会带 `takeover` 重新登记 |
| 主视图写「X 空闲，有 N 条消息没读」 | agent-relay 那次唤醒没生效；0.0.12 起巡视在消息放了 5 分钟后叫醒 Claude 会话（含决策收件箱），叫不醒会通知你；Codex 任务要你手动打开 |
| 主视图第一行写「本次没带 agent-relay 状态」 | 这一轮没读 agent-relay，各线状态无法判断；让决策收件箱按约定先读状态再显示 |
| 主视图第一行写「读不到 agent-relay（原因）」 | 读了但解析失败：agent-relay 是否在运行、决策收件箱是否登记了邮箱名 |
| 主视图写「有 N 条消息没发出去」 | 对决策收件箱说「重发」 |
| 命令提示找不到 `~/.decision-inbox/bin/decision-inbox` | 决策收件箱还没接入；或开一个新会话，让插件重新写一次 |
| 状态文件出问题 | 运行 `~/.decision-inbox/bin/decision-inbox store show <协作组>` 看一致性检查 |
