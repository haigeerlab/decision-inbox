# Spec: wait-closed-item

> 能力图模块 `wait-closed-item`（2026-10-19 用户确认插入，排在 decision-cards 之后）。来源：`livesaas-integration/DECISION-INBOX-ISSUES-2026-10-19.md` 的 I-11（收件箱这一侧；module-crew 那一侧「结项后关掉为它开的等待记录」已在 module-crew 0.6.0 的 MC-7 做了）。用户 2026-10-19 定：先做完它再发 0.0.30。

## 目标

等待记录等的那件事已经有了结果时，收件箱不再拿它报「全线停住」：等的是用户的答复，答复一发出就自动关掉；等待内容里点名的待决事项已经结项的，标「可能已失效」，提醒你关掉。

## 现状（已核对 v0.0.29 之后的 main a0790f0 与 di-p0 真实数据）

- di-p0 的等待记录 W8738：rh2-coord 写「在等谁：决策收件箱（di-p0-hub）」「等什么：#47（epsilon 的 Plan，C128）的【用户答复】转达……」。#47 的答复 21:51 已发出（agent-relay #8787），#47 21:51 已结项，W8738 至今开着。
- 原因一：`tickets.USER_TARGETS` 只认一字不差的「用户」「决策收件箱」「收件枢纽」。写成「决策收件箱（di-p0-hub）」既不算等用户，也对不上名册（名册里收件箱的线名是「决策收件箱」、邮箱名是 di-p0-hub），所以答复发出时的自动关闭（关闭理由 3「所等的事已发生」）没轮到它，收件时还提示「不在会话名册里」。
- 原因二：「可能已失效」只看发送方后来又发过消息，而且明确跳过模块协调（模块协调替多个模块说话）；rh2-coord 是模块协调，所以这条一直算进「全线停住」，主视图报「全线停住 34 分钟：卡在决策收件箱」。

## 要你确认的假设

1. 「在等谁」去掉末尾的括号说明（全角或半角，例如「（di-p0-hub）」）后，等于「用户」「决策收件箱」「收件枢纽」，或等于名册里收件箱会话的线名、邮箱名，就算在等用户。
2. 「等什么」里写了 #N、N 是这个发送方自己的待决事项，并且这一项已结项（已结束、已取代、已撤回）时，这条等待记录**只标「可能已失效」，不自动关**——它等的可能不止那一项（例如「#47 转达后再开工」），关不关由你说「关掉 W编号」。模块协调的等待记录也照这条判（这条看的是它自己点名的待决事项，不是猜）。
3. 已经开着的旧记录（如 W8738）不回溯处理：升级后下一次有答复发出时按新规则自动关；在那之前按假设 2 标「可能已失效」，不再算全线停住。

## 要做的

1. `tickets` 加一个判断「在等用户」的函数，按假设 1；收件、答复发出后自动关闭、主视图的「全线停住」、`/lines`、`/flow`、`/map` 里原来比对 `USER_TARGETS` 的地方都改用它。收件时认出是等用户的，不再提示「不在会话名册里」。
2. 「可能已失效」加第二个来源（假设 2）：所等的 #N 已结项。「看等待」里写「（可能已失效：所等的 #47 已结项，回『关掉 W8738』）」；原来「之后又发过 #M」的写法不变；两个来源都有时写结项那条。
3. 标「可能已失效」的照旧不算进「全线停住」，`/flow` 里的说法照旧。
4. README「日常使用」表里「关掉 W5」那一行、「排查」表「报『全线停住』但有线在干活」那一行补上新的两种情况。

## 做 / 不做

- 做：上面 1～4。
- 不做：自动关掉「所等的 #N 已结项」的记录（假设 2）；改 module-crew（它那一侧已在 0.6.0 做了）；改契约；升级 di-p0。

## 验收标准

1. 「决策收件箱（di-p0-hub）」「决策收件箱(di-p0-hub)」「di-p0-hub」「用户」都认作等用户；「前端（fe）」照旧按名册找前端那条线。
2. 发送方等用户、等待内容写了自己的 #N：#N 的答复发成功后这条记录以理由 3 自动关；没发成功时不关。
3. 用 di-p0 真实的 W8738 与 #47 造的用例：#47 已发出答复并结项 → W8738 被关或标「可能已失效」，主视图没有「全线停住…卡在决策收件箱」。
4. 模块协调的等待记录点名的 #N 已结项（结束、取代、撤回）→ 标「可能已失效：所等的 #N 已结项」；#N 还在等你答 → 不标。
5. 收件时「在等谁：决策收件箱（di-p0-hub）」不再出「不在会话名册里」的提示。
6. 全部单测通过；每条修复先有一条在 a0790f0 上失败的测试。

## 风险

- 「在等谁」的括号去掉后误把某条线当成用户：只在去括号后完全等于那几个名字时才算，线名本身带括号的线（目前没有）不受影响，因为先按原样比对名册。
