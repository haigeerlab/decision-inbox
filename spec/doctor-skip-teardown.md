# Spec: doctor-skip-teardown

> 能力图模块 `doctor-skip-teardown`（2026-10-19 用户确认插入，排在最后，不插队）。来源：2026-10-19 卸载旧测试组 di-e2e、pp-probe 后，doctor 仍报这两个组「巡视 N 分钟没跑」；插入时的假设 1–5 用户 2026-10-19 确认。

## 目标

协作组已经卸载（决策收件箱已退出）时，doctor 不再把它的巡视当成异常，改成一行 ✔ 说明已卸载。

## 现状（已核对代码与实跑）

- `doctor.run` 对 `~/.decision-inbox` 下的每个协作组都调 `_patrol`（`decision_inbox/doctor.py`）。只要 `onboarding.json` 里还记着 `patrolTask` 或 `patrolSession`，就按 `hub.patrol_alarm` 判断巡视停没停。
- `onboard teardown --confirm` 只把决策收件箱记进 `onboarding.json` 的 `left`，不删巡视登记，也不删状态目录。
- 实跑：di-e2e、pp-probe 卸载后，`left` 里已有它们的收件箱（di-e2e-hub、di-pp-hub），doctor 仍报「巡视 2487／2753 分钟没跑」，处理建议还让人去看已经不存在的定时任务。
- 协作规则段的检查已经跳过 `left` 里的条目，这两个组没有报规则段问题。

## 要做的

1. **判断已卸载**（假设 1）：名册里所有 `role` 为 hub 的条目都在 `left` 里，就算这个组已卸载。名册里没有 hub 条目时不算已卸载，按现在的做法检查。
2. **doctor 显示**（假设 2）：已卸载的组，巡视一项显示为 ✔：「<组> 的决策收件箱已卸载（<退出时间>），状态目录保留，不再检查巡视」。不算异常，也不给处理建议。有多个 hub 条目时，取最晚的退出时间。
3. 其他检查不变：协作规则段、Codex 钩子信任、版本、依赖照旧。

## 关键决策与取舍

1. **只改 doctor**（假设 3）：主视图、巡视、`query` 都不动。已卸载的组没人再看它的主视图，巡视也已经停了。
2. **不删数据**（假设 4）：卸载命令照旧保留巡视登记和状态目录。判断看的是 `left`，不靠删登记。
3. **用 ✔，不用「未知」**：卸载是用户确认过的状态，不是异常，也不是读不到；合计里不算进异常。

## 范围

做：`decision_inbox/doctor.py`、`tests/test_doctor.py`。

不做：
- 不改卸载命令和状态目录；
- 不改主视图、巡视、查询；
- 不动版本号：另开 PR，冻结和安装切换另请用户批准（假设 5）。

## 验收标准

1. 收件箱已退出、巡视登记还在、巡视很久没跑的组：doctor 的巡视一项是 ✔，文字含「已卸载」和退出时间，不计入异常。
2. 收件箱没退出的组：巡视停了照样报 ✘，没停照样 ✔，原有测试不变。
3. 名册里没有 hub 条目的组：按现在的做法检查。
4. 实跑：对本机的 di-e2e、pp-probe 跑 doctor，这两组的巡视一项变成 ✔ 已卸载，不再计入异常（di-p0 正在重新接入，其他项的数目以实跑为准）。
5. 全量测试通过。

## 假设

1. `left` 里的时间是 `onboard teardown --confirm` 写入的，格式和其他时间一样（带时区的 ISO 时间）。
