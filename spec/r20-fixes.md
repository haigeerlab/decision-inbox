# Spec: r20-fixes

> 能力图模块 `r20-fixes`（2026-10-19 用户确认插入，排在 approval-display 之后）。来源：`livesaas-integration/BATCH2-SUMMARY.md` 第 3.3 节、REQ-REVIEW-NEARBY 的 R20（用户决定 51，协调人转述；用户 2026-10-19 在本会话确认按建议另开本模块做 ①②③）。

## 目标

1. 你在决策收件箱看到的卡片，就是命令输出的原样，选项字母和「回 N X」不会对不上（O-hub-option-typo）。
2. 多线事项的适用线做完不再误发【已恢复】，结项只认发起方（O-multi-resume）。
3. 停止钩子按工作目录找会话时，不会把已经退出的条目认成本会话（O-who-left）。

④ O-doctor-none 已在 review-nearby（PR #18）修好，本模块不做。

## 现状（已核对代码与演练记录）

1. **字母写错**：插件生成的卡片，每个非推荐选项写的都是「回 N <这个选项的字母>」，字母是对的。批 2 #24 出现「回 24 C」，演练日志写明是收件箱会话自己手抄卡片时抄错的，后来它自己改成了「回 24 B」。收件箱的规则段写的是「原样显示」，但没写「不要手抄、不要改写」。
2. **【已恢复】**：开发线规则段写「收到【用户答复】后，做完要发【已恢复】」，没把多线事项的适用线排除在外。插件本身只按发起方结项（`items.on_resumed` 只关发起方自己的事项），适用线发来的【已恢复】只是多出来的消息。
3. **停止钩子**：`stophook._who` 有两条找会话的路径：给了 `--session` 就按名字找，没给就按 cwd 找名册里 repo 包含它的条目。两条都不排除 `store.left_relays`（已退出的条目）。只给 `--group` 时，一个已退出的条目如果和别的条目共用仓库，会让判断变成「同时属于两个」而放行；或者认到已退出的条目，放行它本该拦的情况。不给 `--group` 时走 `install.locate`，那条路径不受影响。

## 要做的

1. **逐字显示**：
   - 收件枢纽规则段里「原样显示」那两处改成：「把命令输出逐字粘贴给用户，不要手抄、不要改写其中任何一行（包括选项和『回 N X』）；看起来不对时，以命令输出为准，并告诉用户哪里不对」。
   - 加一条自检测试：主视图、「看 N」、「N 详情」里每一行「回 N X」，X 都是同一张卡片里某个选项的字母，而且就是紧挨着它上面那个选项的字母。
2. **多线事项不发【已恢复】**：开发线、审查者、跨线协调三种角色的规则段都在「收到【用户答复】后，做完要发【已恢复】」后面加：「多线事项（事项行里写了『多线事项』）的适用线不用发【已恢复】，结项只认发起方」。
3. **停止钩子排除已退出的条目**：`_who` 两条路径都跳过 `store.left_relays(g)` 里的条目。`--session` 指向已退出的条目时放行，原因写「<名字> 已退出协作组」；按 cwd 找时，已退出的条目不参与匹配。
4. 约定块改了，README 升级一节写明要重新 join（和 approval-display 那一条合并成一句）。

## 关键决策与取舍

1. **①只改规则文字，加测试守住插件输出**：字母是会话手抄时写错的，插件改不了会话的行为，只能把规则写死，并用测试保证插件自己的输出永远对。
2. **②只改规则文字**：插件的结项逻辑本来就对，不需要改代码。
3. **③两条路径都排除**：已退出的条目不该参与任何判断，和 rehearsal2-fixes 里「线状态跳过已退出条目」是同一个原则。

## 验收标准

1. 收件枢纽规则段里有「逐字粘贴」「不要手抄、不要改写」；字母自检测试覆盖主视图、「看 N」、「N 详情」，含推荐项排在前面的情况。
2. 三种角色的规则段都有「适用线不用发【已恢复】，结项只认发起方」。
3. 停止钩子：
   - 只给 `--group`、按 cwd 找时，已退出的条目不参与匹配；原来会误判成「同时属于」的场景，现在能认对本会话，并按规则拦或放行；
   - `--session` 指向已退出的条目时放行，原因写明「已退出协作组」；
   - 原有停止钩子测试全部通过。
4. 原有测试全部通过。

2. 适用线收到的多线【用户答复】，不需要再给决策收件箱任何回执。
