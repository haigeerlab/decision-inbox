# Spec: rehearsal2-fixes

> 能力图模块 `rehearsal2-fixes`（2026-10-18 预览插入，排在 rehearsal-fixes 之后）。来源：LIVE-SAAS 联合演练批 2 的发现（`livesaas-integration/REHEARSAL-LOG.md`，P2 复核到 T16 各节）。用户 2026-10-18 在本会话确认决定 37：批 2 暂停，先修再测；本模块的修复范围以用户批准的这份 Spec 为准。修好后冻结为 0.0.20，两边固定副本切过去，批 2 整批重测。

## 目标

1. 主视图的线状态说真话：已退出的会话不再出现；会话只是这一轮做完、进程被宿主收起时，不再写「掉线」。
2. 巡视不再卡在权限确认上。
3. 【等待用户】写得不到位时，收件枢纽给出提示（不退回）。
4. join 的两处小问题：提醒「新开会话才生效」；内容没变时不重写规则文件。

## 现状（已核对代码、实测记录与 agent-relay 文档）

1. **已退出条目显示「干活中」**：`health._facts` 遍历整个名册，不排除 `left_relays`。di-p0-tester、di-p0-legacy 退出后，agent-relay 身份还绑在本会话上，本会话一忙，它们就显示「干活中」。批 2 主视图实测。
2. **刚做完一轮就显示「掉线」**：`relay._PRESENCE` 把 agent-relay 的 `stopped` 一律映射成 `offline`，`health._state` 和 `_module_word` 再写成「掉线」。agent-relay 文档写明：Claude 桌面版会收起空闲会话的进程，这时报 `stopped`（不是活会话），消息会等着，用桌面版的会话消息能叫醒。所以负责人刚回完审查结论、alpha 和 beta 每一轮做完，都会显示「掉线」。批 2 实测：bridge_agents 里 di-p0-owner、rh-alpha、rh-beta、rh-coord 都是 `stopped`，可它们都在正常收发。
3. **巡视卡在权限确认**：19:33 那次运行的会话记录显示，它在第 1 步用 Write 工具把 bridge_agents 的结果写进系统临时目录 `$TMPDIR`（`/var/folders/…`），等了 15 分钟权限确认，直到用户点了允许（11:33→11:48Z）。按桌面版文档，上一次没结束，之后到点的运行都会跳过。`onboard allow` 写给收件枢纽目录的放行清单只有 decision-inbox 命令、agent-relay 的 7 个工具和 send_message，没有这个 Write。notify 动作用的 `osascript` 也不在清单里。
4. **【等待用户】写法偏松**：批 2 的合批事项缺「项目：」、要点每项只有首行、「你该回：A」只写字母、「架构审查：通过，附建议1条」的括号里没写建议内容，0.0.19 全部判为合格，没有提示。
5. **join 的两处**：后续步骤没有「新开会话才生效」；`_commit` 不管内容变没变都重写规则文件（mtime 变了，输出却写「没有变化」）。

## 要做的

1. **已退出条目不进线状态**：`health` 判线状态时跳过 `left_relays` 里的条目。主视图各线一行、`lines`、`flow`、信号都不再出现它们。名册里的记录不动（迁移期旧格式的收发、leave 预览都不受影响）。
2. **`stopped` 不再算「掉线」**：
   - Claude 会话报 `stopped`，并且能叫醒（名册里登记了 desktopSession，或者 agent-relay 有 wake 绑定）时，线状态按其他事实判断（阻塞、停住、已结项、N 分钟无活动），不写「掉线」。
   - 并行协调线下的模块会话：`stopped` 写「停着」，不写「掉线」。
   - `unreachable`，以及 Claude 会话 `stopped` 但叫不醒（没有 desktopSession，也没有 wake 绑定）时，仍写「掉线」。
   - 巡视的叫醒逻辑不变（它本来就用 `stopped` 判断要不要叫醒）。信号 4「有消息送不进去」保留，文字改成「停着，有 N 条消息等它」。
3. **巡视不需要额外的权限确认**（两种做法，请选一种或都做；我推荐 A+B）：
   - **A 改写法（插件改）**：巡视的中间文件从 `$TMPDIR` 改到 `~/.decision-inbox/<组>/io/`（收件枢纽本来就用这个目录）。notify 改由插件自己的命令 `decision-inbox notify "<文字>"` 发，这条命令已在放行清单里，不再直接调用 osascript。
   - **B 预配权限（改你的配置，你批准后由 `onboard allow` 写入）**：在收件枢纽目录的 `settings.local.json` 放行清单里加一条 Write 规则，只放行 `~/.decision-inbox/<组>/io/` 这一个目录。
   - 只做 A 不做 B，第 1 步的 Write 仍然会问一次权限；只做 B 不做 A，notify 的 osascript 仍然会问。所以推荐两个都做。
   - 已有的巡视任务要更新提示词。升级说明里写明：升级后重跑 `onboard allow`（预览，确认后写入）和更新巡视任务（预览，确认后写入），两步都要用户确认。
   - 宿主调度本身不按时触发的问题（10-18 实测，另一个每日任务也漏跑）不在插件能修的范围内。重启桌面版后的观察结果出来后，如果仍然不触发，再单独决定要不要加兜底（比如巡视停太久就弹通知），本 Spec 不含。
4. **【等待用户】写法提示（只提示，不退回）**：收件枢纽收下后，在主视图那一项和给发件人的回执里列出提示：
   - 缺「项目：」；
   - 「你该回」只有选项字母，没写完整回复原文；
   - 「架构审查」写了「附建议N条」，括号里却没有内容；
   - 要点里每一项只有一行，而事项要决定的不止一件（合批）。这一条的判定条件在 Plan 里定细，先用实测样例 bodies/8.txt 验证。
   退回条件不变（必填字段、选项、是否完全停住等）。
5. **join 提示与不重写**：
   - 后续步骤加一条：「约定块要在新开的会话里才生效：已经开着的会话，请新开一次」；
   - 规则文件内容和原来完全相同时，不写文件，输出照旧写「没有变化」。
6. **文档与版本**：README 的排查表加「刚做完一轮显示掉线」「巡视卡在权限确认」两行，升级一节写明 0.0.20 要重跑 `onboard allow` 和更新巡视任务；版本升到 0.0.20；约定块不变。

## 关键决策与取舍（请重点审）

1. **`stopped` 的判断看「能不能叫醒」**：Claude 桌面版收起空闲会话是常态，把它当「掉线」会让用户每轮都看到误报。真正要你去处理的，是叫不醒的情况（没登记 desktopSession，也没有 wake 绑定）和 `unreachable`，这两种仍写「掉线」。
2. **已退出条目直接不显示**，而不是显示成「已退出」：退出后它就不归收件枢纽管了，留一行只会添乱。leave 预览已经列过它名下没了结的事。
3. **巡视推荐 A+B**：A 把能改的都收进插件已放行的命令里，B 只放行一个固定目录的写入，范围很小。两步都由 `onboard allow` 和巡视任务更新完成，预览后你确认才写。
4. **写法问题只提示不退回**：退回会让会话卡住重发，代价比信息不全大。提示会出现在你看的主视图里，也会回给发件人，让它下次改。
5. **宿主调度不触发不在本模块**：插件改不了宿主，等重启后的观察结果再说。
