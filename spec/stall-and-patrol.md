# Spec: stall-and-patrol

> 能力图模块 `stall-and-patrol`（2026-10-19 用户确认插入，排在 r20-fixes 之后）。来源：REQ-REVIEW-NEARBY 的 R14、R16、R18、R19（用户决定 49、50，协调人转述，用户 2026-10-19 在本会话确认采纳）。R16、R18 的做法依据 2026-10-19 的实测 E0–E4（用户同意，只用临时任务、测试组 di-r18 和临时仓库）。

## 目标

1. **R14 停滞**：一条线或一个模块卡住时，决策收件箱主动问你，而不是等你自己发现。问题里写清卡了多久、卡在哪，选项是：挂起它并先开别的可开工模块（列出来）、换做法、继续等。
2. **R16 常规授权**：第 44 条范围内的常规操作（本地提交、跑测试、改本仓库文件）不再每次弹窗；推送、删除、联网安装、改全局配置这类不可逆操作，仍由你在那个会话里亲手确认。决策收件箱只提醒「去〈会话名〉点允许」并附链接。
3. **R18 巡视会话不堆积**：侧边栏里最多只有一个巡视会话。
4. **R19 叫醒兜底**：消息送到了、对方进程停了、agent-relay 叫醒又一直失败时，巡视在 3 分钟内改用桌面版会话消息叫醒；还叫不醒，就在决策收件箱提醒你去打开，并附链接。

## 现状与实测（2026-10-19）

### R19 为什么没叫醒（只读查 di-p0 的事件日志和名册）

- **#24**：rh2-coord 登记了桌面会话编号。23:28:38 答复发出；23:29 那轮巡视没叫，因为积压不满 5 分钟；23:33 协调人手动叫醒；23:34 巡视才按规则叫醒，已经晚了。积压满 5 分钟才算、巡视每 5 分钟才跑一轮，两者叠加，最坏要将近 10 分钟。巡视也不看 agent-relay 自己叫醒失败了几次。
- **#6811**：22:47:45 答复发出，此后 22:49 到 23:09 的五轮巡视都没叫醒 rh2-coord。说明它在 agent-relay 的状态里既不算「停着」，也不算「空闲且积压满 5 分钟」。具体原因查不到了：巡视每轮只留最新一份状态快照。

### R18 实测

- **E0（官方文档）**：定时任务每次运行都新开一个会话，没有复用会话的选项，也没有跑完自动归档的选项；删除任务时，它开过的会话会一起归档。
- **E1（跑完自己归档）**：定时任务最后一步调用「归档本会话」，被自动模式的分类器拦下（Blocked by classifier）。改用默认模式，每次都要你批准。**不可行。**
- **E2（一个会话用 /loop 5m 循环巡视）**：在测试组 di-r18 上跑了 6 轮，**通过**：侧边栏始终只有这一个会话；6 轮都没弹权限确认；每轮间隔 4 分 39 秒到 4 分 47 秒（见末尾「E2 结果」）。

### R16 实测

- **E0（官方文档）**：CLAUDE.md 和 CLAUDE.local.md 里的文字不影响权限确认，只有 settings 里的 `permissions` 规则说了算。写法是 `Bash(git commit *)`；判断顺序是先拒绝、再询问、最后放行。
- **E3（Claude，临时仓库 r16-claude，规则写在 `.claude/settings.local.json`）**：
  - `git add`、本地提交、跑测试两轮都没弹窗；不在规则里的写文件命令照常弹窗。
  - `ask` 规则在你自己开的会话里有效：推送前弹了确认框（E3b）。
  - 但在我替你开的会话里，推送两次都没弹窗，直接执行了。我只读查了全局设置、应用记录的项目授权和上级目录，都没找到原因。**这是宿主层面的观察，要报给宿主那边，也要提醒 module-crew：它开出来的模块会话可能同样不弹。**
  - **更正（2026-10-19，permission-closeout）**：复查这个代开会话的记录（`~/.claude/projects/-Users-vilin-Documents-haigeerlab-r16-claude/7d26730f-….jsonl`），权限模式是 `default`，两次 `git push` 的 `permissionDecision.source` 都是 `user_temporary`——弹了确认、被点了允许，不是「没弹」。module-crew 的补测会话同样如此（用户决定 67）。上面这句保留作历史记录。
- **E4（Codex，临时仓库 r16-codex，授权写在 AGENTS.md）**：项目还没被信任时，Codex 第 1 步就停下等批准。guardian 对推送会怎么处理，放到阶段丙实测（你 2026-10-19 定的）。

## 要做的

### R19 叫醒兜底（优先，阶段丙前必须稳）

1. 巡视第 1 步除了 `bridge_agents`，再读收件枢纽发出的消息的投递情况（agent-relay `bridge_outbox`，身份写收件枢纽；它给出每条未确认消息的叫醒结果，叫不醒时写 `pendingReason`：offline、unreachable 或 busy）。收件枢纽发给某个 Claude 会话的消息 `pendingReason=offline`，并且已经等了 3 分钟以上，就判定「agent-relay 叫不醒」。这个判定不看它的 presence，#6811 那种情况也能兜住。
2. 判定后，用桌面版会话消息叫醒它，要求名册里登记了 desktopSession。
3. 下一轮还没好，或者名册里没登记 desktopSession，就在决策收件箱主视图最上面提醒：「去打开〈会话名〉：<桌面版链接>」。Codex 会话显示 not-loaded 时，同样提醒你去打开那个 Codex 任务。
4. 原有的「空闲且积压满 5 分钟」改成 3 分钟。
5. 每轮巡视留存当时读到的 agents、outbox 快照（保留最近 24 份，放在协作组 io 目录），出了问题能查原因。

### R18 巡视会话不堆积（做法以 E2 结果为准）

- **E2 通过时**：巡视改由一个专门的「巡视会话」跑：`hub-setup` 时预览，你确认后开这个会话，里面用 `/loop 5m` 执行巡视提示词。
  - 原来的巡视定时任务，你确认后删除；删除时它开过的旧会话会一起归档，侧边栏就清干净了。
  - 应用重启、巡视会话停掉时，靠 hub-patrol 已有的「收件枢纽被叫醒时顺带巡视」兜底；doctor 检查巡视会话还在不在，不在就提示你重开。
- **E2 不通过时**：回来找你定别的办法，不在本 Spec 里擅自定。

### R16 常规授权

1. **Claude 会话**：join 时，预览后经你确认，在这条线的仓库里写 `.claude/settings.local.json`：
   - 放行：`git add`、`git commit`、本线的测试命令；测试命令在 join 时指定，默认不写。
   - 询问：`git push`、`git reset --hard`、`rm -rf`、`npm install`、`pip install` 等。
   - 这是改你的配置，每次 join 都要预览、逐次确认。
2. **Codex 会话**：
   - 约定块写明第 44 条的授权范围，以及不可逆操作必须你亲手确认。relay-checkpoint-authority 已有的「检查点答复即授权」照旧。
   - join 把「先在 Codex 里信任这个项目」列为必做步骤；doctor 发现 Codex 加载不到约定块时报异常（已有）。
3. **提醒**：会话因为权限确认停住时（agent-relay 的 presence 为 `waiting-approval`，主视图已有「要你去原会话亲自确认」卡片），卡片上加上桌面版链接或 Codex 任务名。决策收件箱不代你批准。
4. 把「代理替你开的会话里 ask 规则不生效」写进 README 的使用注意事项，并转告 module-crew 核对它开模块会话的方式。

### R14 停滞提问

1. **触发条件**（阈值放在协作组配置里，可改）：
   - 一条线停住（信号 3）超过 12 小时；
   - 同一个模块的同一个节点反复返工 3 轮以上（信号 7）；
   - 同一个会话就同一件事（「要你决定」第一行相同，或同一模块、同一节点）在 24 小时内抛了 3 次以上。
2. **提问**：决策收件箱生成一件「巡视发现的待决事项」，写清这条线或这个模块卡了多久、卡在哪（最后一次进展、在等什么），选项：
   - A：挂起它，先开下面这些可开工模块（从 /map 的 `ready` 和 module-crew 出口列出）；
   - B：换做法（请写明怎么换）；
   - C：继续等，N 小时内不再问。
3. **答复怎么送达**：用 B（见「已定事项」）：叫醒那条线，请它自己抛【等待用户】；30 分钟内没抛，就在主视图列出三个选项。
4. 选 A 时，挂起由那条线的会话用 spec-guard 现有的 `module-suspend` 执行，决策收件箱不代做。

## 关键决策与取舍（请重点审）

1. **R19 改看 agent-relay 的叫醒状态，不只看 presence**：#6811 说明只看 presence 会漏。阈值从 5 分钟降到 3 分钟，最坏延迟从近 10 分钟降到约 8 分钟。巡视每 5 分钟一轮的节奏不变。
2. **R18 用一个会话循环，不再每次新开**：E1 证明自己归档行不通。代价是这个会话会一直开着，要靠 hub-patrol 兜底它被停掉的情况。
3. **R16 的 Claude 侧落到 settings 规则，不写 CLAUDE.local.md**：文档和 E3 都证明只有规则说了算。代价是要改你仓库里的本地配置，每次 join 都要你确认。
4. **R16 的已知缺口如实写出**：代理替你开的会话里 ask 规则没生效，这是宿主问题，插件补不上，只能提醒和上报。
5. **R14 只提问，不代做**：挂起、换做法都由那条线自己执行，决策收件箱只负责把问题递到你面前。
