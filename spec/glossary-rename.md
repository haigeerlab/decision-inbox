# Spec: glossary-rename

> 能力图模块 `glossary-rename`（2026-10-19 用户确认插入，显式插队；stall-and-patrol 只剩冻结后实测）。来源：术语表 v1.1（`livesaas-integration/GLOSSARY.md`，用户决定 48）；插入时的假设 1–7 用户 2026-10-19 确认。

## 目标

你在决策收件箱、命令输出、README 和各线规则段里看到的名称，和术语表 v1.1 一致；随时能用一条命令查术语表。

## 现状（已核对代码）

- 旧称在代码里给用户看的文字中大量出现：收件枢纽 60 处、事项 95 处、约定块 22 处、负责人 26 处等；README、`commands/*.md`、`skills/decision-inbox-join/SKILL.md` 同样。
- 等待单和事项共用一套编号，都显示成「#数字」；「关掉 #编号」关等待单。术语表规定「#数字」只给待决事项，等待记录用 W 前缀。
- 收件箱自己在名册里的线名存的是「收件枢纽」（`onboard.py` 写入），已接入的组里存的就是这个值。
- 各线规则段（协作规则段）由 join 写进线的规则文件，doctor 会比对规则段是否最新，旧组升级后会提示重新 join。

## 要做的

### 1. 换名称（只换给人看的文字）

| 旧称 | 新名称 | 备注 |
|---|---|---|
| 收件枢纽 | 决策收件箱 | |
| 总协调 | 跨线协调 | |
| 负责人 | 审查者 | 「插件负责人」不出现在给你看的内容里 |
| 短名 | 线名 | |
| 身份名 | 邮箱名 | |
| 协调会话、并行协调 | 模块协调 | 显示时带项目名 |
| 事项 | 待决事项 | 只在指收件箱里那件等你决定的事时换；「多线事项」不变 |
| 适用会话 | 适用的线 | |
| 等待单 | 等待记录 | 编号显示为 W 前缀，见第 2 条 |
| 【已恢复】（显示时） | 已结项 | |
| 负责人转交 | 审查者转交 | |
| 约定块 | 协作规则段 | |
| 用户答复 | 你的答复 | |
| 待用户决定（显示时） | 待你决定 | |
| 审批、评审 | 批准或审查 | 按术语表第五节：审查者做的叫审查，你做的叫批准 |

**不换的**：
- 契约里的消息标签和字段名：【已恢复】【用户答复】【负责人转交】【等待用户】等标签，「适用会话」「待用户决定」等字段名。各线发消息仍按契约写，插件读消息的规则不变。
- 规则段里要线照着写的标签和字段名照写，第一次出现时括号注明新名称，例如「发【已恢复】（表示已结项）」「写『适用会话』一行（列出适用的线）」。
- 代码标识符、JSON 键、`~/.decision-inbox` 里的数据文件名、命令名（如 `/decision-inbox:item`）。
- 已批准的旧 Spec 和能力图开头的「目标」段（Proposal 的指纹底本）。显示用词以本 Spec 和术语表为准，取代旧 Spec 样例里的写法。

### 2. 等待记录用 W 编号

- 主视图、「看 N」、等待记录列表、leave 预览、停止钩子提示、健康提醒里，等待记录显示成「W3」，不再显示「#3」。编号数字不变，仍和待决事项共用一套计数。
- 「关掉 W3」可以关等待记录。「关掉 #3」继续可用（旧习惯），但回复里写成 W3。
- 「看 W3」能查等待记录；「看 3」或「看 #3」指向等待记录时也能查到，显示用 W3。
- 契约消息（【已恢复】「结束：#编号」）里仍按契约写 #编号，插件照旧读取。

### 3. 收件箱自己的线名

- 新建组时，收件箱的线名写「决策收件箱」。
- 已接入的组里存的仍是「收件枢纽」，显示时一律换成「决策收件箱」。不改数据文件。
- 其他线的线名不能用「决策收件箱」或「收件枢纽」（实现时补充，用户 2026-10-19 验收时确认）：收件箱改名后，原来「和收件箱线名重复」的拦截会失效，这条把它补上。

### 4. 术语表帮助页

- 插件带一份术语表 v1.1 副本 `docs/glossary.md`，开头注明来源（`livesaas-integration/GLOSSARY.md`）、版本和日期。
- 新增命令 `/decision-inbox:glossary`：运行 `decision-inbox glossary`，把副本原文逐字显示，不改写、不总结。Codex 线用同一个 CLI 子命令。
- README 开头附近加一句「名称不清楚就用 `/decision-inbox:glossary` 查术语表」。

### 5. 升级

- README 升级一节写明：这一版改了协作规则段的用词，已接入的线要重新 join，规则段才会换成新用词；doctor 会提示哪条线的规则段过期。旧数据不用迁移。

## 关键决策与取舍

1. **只换显示，不换契约**：契约标签由契约负责人评估，涉及主版本的留到观察期以后（术语表原文）。所以规则段里线要写的标签照旧，只在旁边注明新名称。
2. **W 编号只在显示层**：编号空间不拆，避免数据迁移；「关掉 #3」保留兼容，免得旧习惯一下子失效。
3. **旧 Spec 不逐份改写**：35 份已批准的 Spec 样例里有旧称，逐份改要逐份复审，成本远大于收益。由本 Spec 统一声明取代。
4. **帮助页带副本而不是链接外部文件**：用户机器上不一定有 livesaas-integration 仓库，插件要自带。

1. 「事项」只在指收件箱那件等你决定的事时换成「待决事项」，复合词（多线事项、单线事项）不动。
