# Spec: proxied-session-note

> 能力图模块 `proxied-session-note`（2026-10-19 用户确认插入，排在最后，不插队）。来源：接入协调人转来的 DI-2 相关风险（用户 2026-10-19 在接入协调会话同意转来）；用户 2026-10-19 在本会话同意「按建议处理」：先做提醒这一条，识别代开会话、改用 deny 或钩子等查证与实测后再定。插入时的假设 1–5 用户 2026-10-19 确认。

## 目标

用户和工作会话都知道：「先问」规则只对用户亲手开的 Claude 会话可靠；被别的会话代开时，不可逆操作不要直接执行，按「去会话操作」上报，等用户亲手去点。

## 现状（已核对）

- **实测依据**：stall-and-patrol 的 E3（`spec/stall-and-patrol.md`）——用户亲手开的会话里推送前弹了确认；本插件替用户开的会话里推送两次都没弹确认、直接执行了，原因不明（宿主层面）。
- **已有提醒**：README「使用注意事项」第 158 行写了这一条，但接入预览和协作规则段里没有。
- **相关规则**：
  - scope-authority-defaults 起，Claude 线的「先问」规则是推送、`reset --hard`、`rm -rf`；加新包不写规则，交给宿主默认处理，规则段要求先问一次。
  - go-to-session 起，规则段有「停在宿主确认上」一节，接入预览有一行说明会出现「要你去会话里操作」一栏。

## 要做的

1. **接入预览**（假设 1）：Claude 会话（`host == "claude-desktop"`）接入时，提醒（⚠）里加一行：「『先问』规则只对你亲手开的会话可靠：别的会话代开的会话里，推送等操作可能不弹确认就执行（2026-10-19 实测）。由别的会话代开的线，规则段要求它碰到不可逆操作时先到决策收件箱请你去点。」Codex 会话不加。
2. **规则段**（假设 2）：开发线、审查者、跨线协调的规则段，在「停在宿主确认上」一节末尾加一条：「如果你是被别的会话开出来的（开工说明由别的会话发来，不是用户在本会话里亲手输入的），碰到不可逆操作（推送、`reset --hard`、`rm -rf`、往项目里加新包）不要直接执行：按上面的格式抛『去会话操作』，『为什么批不了』写『本会话由别的会话代开，先问规则可能不弹确认』，等用户去本会话亲手确认。」
3. **README**（假设 4）：第 158 行补一句「协作规则段也写了这一条：被代开的会话碰到不可逆操作会先到决策收件箱请你去点」；升级一节写明协作规则段又改了，与 R21 其他模块一起重跑接入。

## 关键决策与取舍

1. **会话自己判断是否被代开**（假设 2）：本插件读不到「谁开了这个会话」，先靠规则段让会话按开工说明的来源自判。自动识别要先查清数据来源，另定。
2. **只改文字**（假设 3）：ask 不改成 deny，不加钩子守门；等协调人那边「代开会话没规则时弹不弹默认确认」的实测出结果，再请用户定。
