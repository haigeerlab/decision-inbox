# Spec: protocol-contract-v2-6

> 能力图模块 `protocol-contract-v2-6`（2026-10-22 用户确认插入，排在 stage-c3-fixes 之后）。来源：统筹派活，契约 session-protocol v2.5（566f0de，模块 light-task-field）与 v2.6（92309e7，模块 review-display-unify），两版都已经用户批准。和 stage-c3-fixes 一起出 0.0.37。

## 目标

decision-inbox 钉到契约 v2.6（包含 v2.5），新增内容都能读、都能答：
- 轻任务的「任务：T<n>」；
- C 待定编号（C15-1）；
- Spec 和 Plan 的新小项名。

契约样例全部跑通。消除「C15-1 B」被读成答事项 1、「T78」被当成事项号这两类误读。

## 现状

- `protocol.CONTRACT_VERSION = "2.4"`，样例目录是 `tests/fixtures/session-protocol/v2.4/`；`tests/test_contract.py` 按版本目录逐份跑样例，并核对 `SHA256SUMS`。
- 「待用户决定」只认 `D数字`（`protocol.py:285`）；用户回复里待定问题的答法只认 D（`items.py:366`）。
- 编号前缀只认 C、D、R（`items.py:315`），不认 T。
- 0.0.36 的行内切分（`items.py:318` `_INLINE_RE`）和夹带检查会把「41 A；C15-1 B」里的「1 B」当成答事项 1。契约 v2.6 的兼容性说明也点名了这一点。
- Spec 卡的固定小项是「目标、做／不做、要你确认的假设、验收标准、附带的小决定」，Plan 卡是「分几步、会改哪些文件、风险、中途会停下来问你的地方」（`protocol.py:414-415`），不认新名。
- 统筹在沙箱里试过：只剩 #78 一项待答时，「T78 先缓一缓」被收成了 #78 的答复。这是 I-20 那一类问题（不带编号的话被收下）加上 T 编号没被认出来。

## 假设（请确认）

1. **版本**：`CONTRACT_VERSION` 改为 `"2.6"`，新建 `tests/fixtures/session-protocol/v2.6/`，内容是契约仓库 92309e7 的 `fixtures/` 原样拷贝（含 `SHA256SUMS`），删掉 v2.4 目录。一致性测试只跑当前钉住的版本，沿用现在的做法。
2. **「任务」（v2.5）**：
   - 【等待用户】【审查结论】读选填字段「任务」，合格时原文进 `task`（比如「T3」），没写或格式不对时为 null。
   - 格式不对报 `bad-task-ref`；「模块」不是「无」又写了「任务」时报 `module-task-both`。两个代码排在各类型原有问题代码之后，按契约第 7 节的顺序。
   - 【交审】【协调通知】本插件照旧不解析。
   - **显示**：带「任务」的卡，在卡片抬头的模块位置显示「任务 T3」。
   - **打转检测**：这类事项不按模块归类，`module` 不从「任务」推出来。轻任务的打转检测这次不做。
3. **T 编号不当事项号**：用户回复里的「T数字」和 C、D、R 一样算带前缀的编号，原样留在用户原话里。只剩一项待答时，「T78 先缓一缓」按 stage-c3-fixes 的规则追问，不收成答复。
4. **C 待定编号（v2.6）**：
   - 「待用户决定」的条目头认「C数字-数字：问题」，`decisions` 的 `id` 是「C15-1」；`bad-decision-item`、`duplicate-decision` 冒号后可以接 C 待定编号。
   - 用户答法「C15-1 B」「C15-1：B」「C15-1 选 B」都认，和 D 编号一样整条核对：没答全就整条追问，不转发半截答复。
   - 行内切分和夹带检查遇到前面紧挨「-」或字母、数字的数字，不当事项号。所以「41 A；C15-1 B」只答 #41，C15-1 选 B。
5. **新小项名（v2.6）**：
   - Spec 卡认「边界」「未决问题」，Plan 卡认开头的「架构决定」和末尾的「未决问题」。
   - 旧名照认；新旧名各记各的，`points` 里保留原名，同时出现时两行都显示，不换算。
   - 最终验收「验收结果」的小项名不变（契约只是写明要逐条写证据），显示照旧。
6. **样例**：v2.6 目录里本插件解析的类型（【等待用户】【审查结论】【用户答复】等）全部按期望结果跑通，其中点名的 8 份是：
   - wait-user/task-escalation、task-module-both、task-bad-ref；
   - review-conclusion/task；
   - wait-user/decision-cnum、decision-cnum-bad、card-spec-upstream、card-plan-upstream。

   【交审】【协调通知】的样例照旧跳过，沿用现有规则。
7. **规则段**：收件箱规则段写明认 T 编号与 C 待定编号、卡片显示新小项名。开发线的规则段不改，它们按自己的插件（module-crew、spec-guard）写卡片。
8. **版本号**：本模块最后一个任务把两个 plugin.json 升到 0.0.37，README 写 0.0.37 的完整说明（包括 stage-c3-fixes）。
